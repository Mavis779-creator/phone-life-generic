# 脚本导入与内容工作室

1.2 版提供一个本地内容编辑入口，以及可选的 AI 脚本编排器。空白安装仍没有人物、聊天和剧情。提示词不是可玩的剧情预设。

## 入口与最短流程

开始页可直接点击“导入脚本”或“手动创作”，不需要先解锁。无人物时，手动创作先打开人物草稿；已有手机人物时打开对话编辑。从开始页进入的创作会话，根页面返回或主页手势会回到开始页；进入手机体验仍需解锁。

也可打开手机的“设置 → 内容工作室 · 脚本、对话与平台帖子”。AI 控制台也有“导入脚本 / 手动编辑”按钮。

1. 如果需要 AI，先按 [AI 启动说明](AI_SETUP.md) 启动自己的后端，填写连接码并启用 AI。
2. 在“脚本导入”选择自己的 TXT / MD 文件，或直接粘贴正文。导入这一步只在本地保存。
3. 填写改编要求：玩家是谁、关系进行到哪一步、从哪段开始、允许哪些平台参与、不要发生什么。正文中已有的具体设定优先。
4. 选择写作侧重，按需要修改提示词，然后点“AI 识别并编排”。这一步才把正文与要求发给模型。
5. 在“剧情编排”查看改编范围、待核对假设、人物、节点、分支和联动。可先到“人物群聊”改口吻和资料，再编辑各个节点。
6. 点“检查依赖与内容”。检查通过后，点“安装并开始”，确认替换当前主线。
7. 开场消息立即送达锁屏/通知和对应应用。进入聊天后普通消息逐条出现，遇到选择时等玩家回应，再解锁后续会话。

AI 结果不会自动写入联系人或开场。没有点击安装时，它只是草稿。安装后的运行副本与草稿分开保存：修改草稿不会悄悄改变已经进行的章节。

## 支持的文件与篇幅

- UTF-8 `.txt` / `.md`：正文最多 50000 字符，文件最多 220KB。不会截断后假装已经阅读完整脚本。
- `.json`：最多800KB，导入本工作室导出的结构化剧本包，先进行完整校验，再保存为草稿。
- Word / PDF：本版不直接提取，请先另存或复制为纯文本。
- 长篇建议逐章改编。模型要生成一个有开头、变化与收束的可玩章节，并在改编分析中说明覆盖范围，不声称已经改编整部长篇。
- 一个包最多 24 人、8 个群、60 个节点；每节点最多 40 条消息、6 个选项和 12 项联动。实际建议先用 6–12 个节点试写一章。
- 后端脚本输出上限单独使用 `.env` 中的 `AI_SCRIPT_MAX_OUTPUT_TOKENS=16000`，不影响普通回复的输出预算。编排超时约三分钟。输出不完整时保留旧草稿，可缩短章节后重试。

## 自然写作提示词

内置提示词可编辑，位于 `src/writing-prompts.js`。三个侧重是“日常慢热”“群像与多线”“克制与张力”。普通 AI 回复也会使用通用自然写作要求。

这些要求从人物动机、说话习惯和信息来源入手：人物有自己的事情和不愿说的话；对话长短不齐，有省略、补发和具体生活细节；不同平台留下不同痕迹。避免每句反问、无条件安慰、机械撩拨和总结陈词。重大关系和承诺由玩家决定，缺失设定列为待核对项。群里不要求每个人轮流报到，私聊内容不能无理由成为公开消息。

编写时参考了 [BookTrust 的同人创作建议](https://www.booktrust.org.uk/resources/find-resources/writing-fan-fiction-a-beginners-guide/) 中对原设一致性与人物动机的讨论，以及 [Novlr 的人物口吻建议](https://www.novlr.org/the-reading-room/how-do-you-get-into-a-characters-head-when-writing-fanfiction) 中对句长、词汇、反应和价值取向的观察方法。项目没有内置或抓取具体同人小说正文，也没有模仿某位作者的原句。

提示词是写作约束，不能保证每个模型输出的文学质量。先用自己的短脚本试写，核对人称、称呼、关系阶段与公开/私密信息，再调整提示词和内容。

## 不接 AI，自己编辑

所有手工编辑功能在离线文件页面也能使用，不要求开启 AI。

### 对话编辑

先在“人物与世界”添加手机联系人，或安装自己写的剧本。

“对话编辑”可选择 KakaoTalk 私聊/群聊及 Instagram、X、Threads、TikTok、Weverse 私信，分别补写玩家或角色消息，修改正文、译文、显示时间与引用内容。列表支持上移、下移、编辑和删除。发言人必须属于这个会话。修改媒体消息的文字时保留原媒体字段。

正在推进的会话会阻止直接改写；先点“暂停剧情，进入编辑”。暂停保留节点、选择和游标，完成后可继续。修改已送达消息只改变当前记录；如果还要改变未来对话，请在剧情草稿中改写相应行并重新安装。

### 平台发帖

“平台发帖”可选 Instagram、X、Threads、TikTok、Weverse 和具体账号，选择新帖作者、填写正文与照片/视频描述。可编辑或删除本地已有帖子。修改正文保留原作者、评论、点赞和上传媒体；删除描述只去掉文字描述卡，不移除用户上传的媒体。

所有发布只发生在模拟手机内。发帖不上传到真实平台。文字媒体描述也不会被宣称为真实拍摄的视频或照片。

### 人物、群聊和剧情

“人物群聊”编辑剧本草稿。每个人有唯一标识、姓名、账号、关系类型、背景与口吻。点群名可回填群聊信息，成员使用人物标识，用英文逗号分隔；玩家默认也参与群聊，需至少两位 NPC。

“剧情编排”可新建或编辑节点。一般内容用表单填写：

| 字段 | 填写方式 |
| --- | --- |
| 剧本标题 | 整章标题 |
| 节点标识 | 唯一英文、数字、短横线或下划线；创建后不改名 |
| 消息平台与账号 | 六个平台之一；第一个账号索引为 0 |
| 会话对象 | 草稿人物；群聊仅使用 KakaoTalk |
| 前置节点 | 用英文逗号分隔；留空表示安装即送达 |
| 消息 | 每行 `发言人标识 | 正文 | 中文翻译`；玩家标识为 `player` |
| 关键选择 | 提示与至少两个选项；每行 `选项值 | 玩家回复 | 对方回应`，韩文回应再加 `| 中文译文` |
| 分支与联动 | 展开高级区，修改 `when` 与 `effects` JSON |

第一条必须是角色发来的消息。每行固定三段，空翻译也保留末尾 `|`；正文内请避免使用这个分隔符。复杂多行消息可改用完整 JSON 编辑。韩/日文角色消息需填中文翻译，选项回应可使用中文；韩文回应在第4段填写中文译文。普通玩家行由作者预写，关键分歧由玩家选择。

## 节点与联动数据

`src/authoring-contract.js` 是前后端共用的完整协议。结构化剧本包与旧 `config/scenario.json` 的编译期节点格式不同，不要直接互换。

剧本包字段：

| 字段 | 内容 |
| --- | --- |
| `version` | 固定 `1` |
| `title`, `analysis` | 标题、改编范围/口吻/因果与信息边界说明 |
| `assumptions` | 待玩家核对的设定文字数组 |
| `cast` | `{ref,name,handle,slot,profession,bio,persona}` 数组 |
| `groups` | `{ref,name,members,description}` 数组 |
| `nodes` | 消息节点数组 |

每个节点包含 `id,title,platform,accountIndex,target,dependsOn,when,lines,choice,effects`。这些字段均须存在，无内容的数组使用 `[]`。`choice.options` 每项为三段，韩文回应使用四段（第4段中文译文；需要1.3及以上版本）。`choice` 无选择时为 `{"prompt":"","options":[]}`。

`lines` 每行是 `{"speaker":"人物标识或player","text":"正文","translation":"译文或空字符串"}`。

`when` 是条件数组。每项 `{"nodeId":"前置选择节点","value":"选项值"}`；必须存在从本节点到该选择节点的依赖路径。所有条件匹配才送达，不匹配的节点标为跳过。后续节点可依赖多个分支，等它们完成或跳过后汇合。

`effects` 每项为 `{"at":"start或finish","action":{...}}`。`start` 在开场气泡前触发，`finish` 在本节点普通消息及选择完成后触发。只允许以下两种 action：

| 动作 | 必填字段 |
| --- | --- |
| `publish_post` | `type,author,platform,accountIndex,text,description`；author 使用人物标识或 player；platform 为 Instagram/X/Threads/TikTok/Weverse |
| `upsert_event` | `type,ref,title,date,time,location,notes`；ref 为空字符串，日期 `YYYY-MM-DD`，时间 `HH:mm` |

同一事件无需覆盖全部应用。可以在消息开始时出现一条 Instagram 描述帖，在选择完成后追加日历；其他角色不必知道私聊细节。联动操作有持久化标记，刷新/再次进入不会重复执行。同一章重新安装属于新一轮，按新一轮重新发送与发帖。

完整包可在“剧情编排 → 完整剧本包 JSON 编辑”中修改分析、假设和任何结构字段，也能导出后再导入。保存与安装都会检查无环依赖、有效引用、成员身份、日期、翻译和数量上限。

## 保存、撤销与原有内容

- 输入中的改编要求、编辑表单草稿、当前编辑对象及剧本包在本机存档中保存。刷新后可继续填写；切换到另一个对象时会清除当前表单草稿，请先保存当前编辑。
- 内容工作室保留最近五批可撤销的手工修改；AI 控制台保留自己的五批撤销记录。原内容后来又被改动时会拒绝整批撤销，避免覆盖。
- AI 编排前的草稿可通过“恢复编排前草稿”找回；反复点击可在这两份间切换。草稿只是候选，恢复不重置手机。
- 安装替换当前主线，但保留此前联系人、聊天、帖子和日程。使用同一账号的人物沿用身份；群聊按新一轮创建，不把旧群消息合并进去。
- 安装或批量编辑中任何一步失败/存档空间不足会回滚。安装前建议先“设置 → 导出存档”。编辑器 JSON 导出只包含剧本包，聊天和帖子等当前手机记录请用完整存档导出。
- 原版手机工程未改动，通用版存档键继续独立。源码包/Git 仓库不包含玩家浏览器存档、上传脚本或 API 密钥。用户自己导出的剧本包/存档可能含私人创作，分享前自行检查内容。

## 实现与验证

浏览器：`src/authoring.js` / `src/authoring.css`。共享协议：`src/authoring-contract.js`。提示词：`src/writing-prompts.js`。后端：已认证的 `POST /api/ai/script`，支持 Responses 与 Chat 工具调用适配器。

只发送主动选择的正文、改编要求和写作提示词，不自动附带聊天历史、钱包、PIN 或文件原件。密钥只在后端。调用可停止，迟到或基于旧草稿的结果不会覆盖新草稿。模型只返回数据结构，手机不执行模型提供的代码。

运行 `node tests/authoring.cjs` 和 `node tests/authoring-server.mjs` 检查离线编辑、草稿持久化、分支/跳过/汇合、跨平台联动、撤销和接口联调。后端测试仅使用假密钥和模拟模型，未验证真实模型生成质量；没有浏览器视觉、触摸或设备测试。
